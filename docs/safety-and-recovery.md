# 安全修复与离线验证

2026-10-01 整理。修复覆盖经济定位、写入守卫、车辆恢复、发动机持久化与多功能会话复用。

## 行为变化

- 同一活进程的功能启用沿用现有附加会话。进程句柄申请 SYNCHRONIZE，避免存活检测失败反复重新附加并清空其他功能；真实退出码 259 也能正确识别进程退出。
- 金钱/经验定位遇到同分歧义或候选截断时拒绝自动写入；经验地址直接使用扫描命中的字段地址，并验证其经济对象引用正确的 bank。
- UI 与后台写入共用线程安全的守卫策略；经济定位结果由 UI 消费，后台不直接修改普通 UI 字段。
- 车辆恢复绑定进程代次、车辆型号指纹、地址及逐字段写入凭据。NeedsRestore 只是恢复请求；当前内容不符时隔离，暂不可读时保留重试。Captured 不产生已写入证据，隔离项不被批量更新重新激活。
- CoM 与两个 cvar 独立记账。重新捕获已恢复的 cvar 不覆盖另一个字段仍待恢复的原值；当前代次已隔离的 cvar 不重新捕获。
- 持续链断返回暂停并等待；只有命令序号变化才按过期任务处理。恢复与目标写入都检查命令序号，避免旧的关闭或强度 1 周期覆盖重新启用请求。
- 原重心及事务写入前的当前重心必须为有限数且位于保守范围 [-6,5]；明显异常字段拒绝备份与写入。这个范围可能拒绝特殊车辆/mod，不能证明字段布局正确。
- 发动机事务按逐字段成功写入结果保留预期内容，回滚到本轮之前的值。回滚未确认时保留原厂基准并暂停继续放大，避免残留扭矩被当作新的原厂值。
- 发动机未确认部分事务用恢复记录的可选 `;U` 尾标记持久化。重载后内容不符时保留凭据并拒绝写入；记录自身的倍率与 RPM 标志不受当前 UI 策略影响。
- 发动机后台状态变化通过修订号触发 UI 原子保存设置；多条导入凭据以 `;P;` 分段保留，未核对记录不导出为空。

## 验证

在 Windows / MSVC 构建生产版本与非提权测试版本均成功；最终编译和链接日志未发现 warning/error。

```bat
cd cpp
build.bat test
build\ETS2Trainer_test.exe --selftest
build\ETS2Trainer_test.exe --crosstest
build.bat
```

该次自检为 **139 通过 / 0 失败**，专用靶子跨进程测试为 **13 通过 / 0 失败**。

新增回归覆盖：附加会话连续复用、活进程退出码 259、同址同型号重映射与外部哨兵保护、两个 cvar 的独立恢复、真实车辆事务回滚失败、后台链断等待及指针恢复、关闭/重启交错、首次与后续发动机部分事务、恢复凭据重载、不叠加倍率、外部内容拒绝覆盖、空挡 RPM 残留恢复及异常重心拒绝。

独立旧探针中“直接写合成内存后只标 NeedsRestore”的模拟没有记录写入凭据，当前实现会隔离；这项不能作为放宽恢复校验的理由。真实事务回滚失败的正向恢复另有正式回归测试。

## 验证边界

本轮没有启动、附加或写入 ETS2，没有验证实车全部功能组合效果，也没有确认既往闪退根因。车辆指纹属于型号相关字段，不能当作唯一对象实例标识；恢复还必须通过当前内容核对。未确认的发动机部分事务会保守暂停写入，可能需要先让对应对象重新可读并核对。

仓库只提交源码、构建脚本与不含个人数据的说明。EXE、设置、运行日志、原始报告及独立本机探针继续由 .gitignore 排除。
