# 欧卡2 修改器 (ETS2 Trainer)

一个属于你自己的《欧洲卡车模拟 2》修改器：**游戏运行中实时改钱 / 改经验 / 无限油量 / 无损**，
外加通用数值扫描器、游戏内控制台命令、存档备份与明文存档改数值。

* 不修改游戏 exe、不注入代码，只做内存读写和存档文件读写
* 只在单机使用；检测到 TruckersMP 会警告（联机改内存可能封号）
* 单文件原生程序（Dear ImGui + Direct3D 11），界面内置中文，支持 6 个功能标签页
* 功能：实时改钱 / 经验 · **车辆（无限油量 / 无损）** · 通用数值扫描器 · 游戏内控制台命令 ·
  存档备份还原 · 明文存档改数值

---

## 一、运行与编译

`ETS2Trainer.exe` 是 **Dear ImGui + Direct3D 11** 的原生单文件程序：暗色主题、圆角控件、表格、
进度条、中文界面；静态链接（不需要 VC++ 运行库），双击自动请求管理员权限（UAC）。
**不修改游戏 exe、不注入代码**，只做内存读写和存档文件读写。

共 6 个标签页：

| 标签页 | 作用 |
| --- | --- |
| 实时改钱 / 经验 | 直接改游戏内存，改完立刻生效；可锁定 |
| **车辆（油量 / 无损 / 动力）** | **无限油量 · 永不损坏 · 发动机动力倍率与转速上限**（详见第四章） |
| 数值扫描器 | 类 Cheat Engine 的通用扫描（油量、里程、车速、损坏度……） |
| 游戏内功能 | 把控制台命令直接敲进游戏（时间 / 警察 / 疲劳 / 收入倍率） |
| 存档工具 | 存档列表、备份还原、解密导出、明文存档改数值 |
| 说明 | 使用说明与扫描参数设置 |


### 1.1 运行（最简单）

1. 先启动游戏（**单机**），进入车内或车库。
2. 双击 **`ETS2Trainer.exe`** → 弹出 UAC 时点“是”（读写游戏内存必须要管理员权限）。
3. 点窗口左上角「**附加游戏**」，状态变成「已附加」即可。

> 当前开发版没有商业代码签名，Windows 会在 UAC 中显示“未知发布者”；
> 请只使用你自己从本目录源码编译的产物，不要运行来源不明的同名程序。

### 1.2 自己编译

需要 **Visual Studio 2022 生成工具**（含 C++ 工具集 + Windows SDK）。Dear ImGui 源码已随工程
附在 `cpp\vendor\imgui-1.92.9`（无需联网）。

```bat
cd cpp
build.bat           :: 完整编译，输出 ..\ETS2Trainer.exe（首次约 1~2 分钟）
build.bat check     :: 只做语法/类型检查
build.bat test      :: 编译“免提权测试版” -> cpp\build\ETS2Trainer_test.exe
build.bat clean     :: 清理
```

> 正式 exe 通过内嵌清单（manifest）请求管理员权限，所以双击就会弹 UAC；测试版不带清单，
> 方便自动化测试。构建采用 **“并行编译(/MP) + 单独链接”** 两阶段，避免把全部源文件塞进
> 一个 cl 进程导致编译器堆溢出（C1060）。

### 1.3 自检与实测模式

```bat
ETS2Trainer.exe --selftest                     :: 功能自检（40 项核心检查 + 可选游戏环境检查）
cpp\build\ETS2Trainer_test.exe --crosstest     :: 跨进程端到端测试（13 项）
cpp\build\ETS2Trainer_test.exe --livetest      :: 对运行中的欧卡2 做只读实测
cpp\build\ETS2Trainer_test.exe --smoketest     :: 界面渲染冒烟（30 帧后自动退出）
cpp\build\ETS2Trainer_test.exe --parsetest     :: 明文存档解析调试
ETS2Trainer.exe --enginetest                   :: 只读定位发动机数据对象（有界指针遍历）
ETS2Trainer.exe --fieldprobe                   :: 只读探查变速箱传动比数组是否可达（不写入）
ETS2Trainer.exe --flycheck                     :: 只读检查飞行模式（config.cfg + 相机按键）
ETS2Trainer.exe --citycheck                    :: 只读解密存档并列出 goto 可用的城市内部名
ETS2Trainer.exe --convoycheck                  :: 只读检查联机状态、Convoy 会话与玩家列表
ETS2Trainer.exe --powertest                    :: 【会写内存】临时写入 1.25× 后立即写回，仅在单机下使用
```

* `--selftest`：内存引擎（打开进程 / 枚举区域 / int32·int64·float·double 扫描 / 收窄 / 写入 /
  数值锁定）、进程与联机检测、ScsC 解密（AES-256-CBC + 自写 DEFLATE）、明文存档读写、备份、
  控制台按键识别、取消事务性、锁定器重启清理、车辆面板字段绑定，以及
  **发动机动力调节的离线状态机测试（10 项，用内存镜像驱动，不接触游戏）** →
  **40 项核心检查**；游戏运行时另检查联机特征与游戏窗口。
* `--crosstest`：自己启动一个“靶子”子进程，对它做跨进程 读取 / 区域枚举 / 扫描 / 写入 / 锁定，
  并专门验证 **油量式容差扫描（534 命中 534.75）**、**容差过小时不误命中**、**损坏清零** →
  **13 项通过、0 失败**。
* `--livetest`：附加真实游戏（**全程只读**），只检查固定版本指纹、车辆指针链和遥测值；
  不再遍历整个游戏堆。
* `--enginetest`：只读定位诊断（有界指针遍历 + 字段签名），会打印联机判定结果。
* `--fieldprobe`：只读探查变速箱数据对象里的传动比数组与发动机曲线数组，**不写入任何数据**。
* `--flycheck`：只读检查飞行模式（`config.cfg` 的开发者/控制台/飞行速度、`controls.sii` 相机按键、
  当前是否可以安全写入 config.cfg）。
* `--citycheck`：只读解密存档并提取 `goto` 可用的城市内部名（用于地图传送）。
* `--convoycheck`：只读解析联机判定、Convoy 会话开始时间与在线玩家列表。
* `--powertest`：**会写入真实游戏内存**，仅在单机驾驶界面且你明确同意后手动运行；
  程序内部会先做联机检测，命中就会拒绝执行。

## 二、最重要的功能：实时改钱（3 步）

切到「**实时改钱 / 经验**」标签页：

| 步骤 | 操作 |
| --- | --- |
| ① | 看游戏里现金是多少（比如 `45,678`），把 `45678` 填到「游戏里当前的数值」，点「**① 扫描这个数值**」（约 10~25 秒，有进度条） |
| ② | 如果提示“命中较多”：在游戏里花点钱或赚点钱（买个东西、接个活），把**新数字**填进去，点「**② 收窄:数值变了**」。尽量收窄到 1 个候选；多候选写入会弹出风险确认 |
| ③ | 在「要改成」填目标金额（例如 `999999999`），点「**③ 写入内存**」——游戏里立刻变成新金额 |

想固定住金额（免得被游戏扣费改回去），勾选「**锁定该数值**」。

**经验同理**：类型默认 `int32`，扫描当前经验 → 写入目标经验 → 人物立刻升级、拿技能点。

**改完会被存档保存吗？** 会。游戏开车过程中会自动存档（`autosave_drive`），
它保存的是内存里的当前数值，所以自动存档后你的新金额就写进存档了。

## 三、数值扫描器（任何数值都能改）

「数值扫描器」标签页是简化版的 Cheat Engine：

* 支持类型：`int32 / uint32 / int64 / uint64 / float / double`
* 整数输入通过 `double` 传递，为避免静默精度丢失，当前要求绝对值不超过 `2^53-1`
* 「首次扫描」= 按当前值全内存搜索；「再次扫描」= 精确 / 变了 / 没变 / 变大 / 变小
* 表格里选中若干行 → 「写入选中行」改值、「锁定选中行」固定值
* 浮点数（油量、损坏度、水温）记得把「浮点容差」设成 0.01 左右

例子：改油量 → 类型 `float`，看油量表数字（如 `534`）→ 首次扫描 → 开着车烧点油 →
新数字填进去点「等于新数值」收窄 → 写入 `2000`。

## 四、车辆（无限油量 / 无损 / 动力调节）

「车辆（油量/无损）」标签页不需要手动扫描。程序核对 `eurotrucks2.exe` 1.61.1.1 的固定
版本指纹，再从模块入口沿 4 级动态指针取得当前车辆；不会遍历主模块或游戏内存池。写入前会把
指针中的
油量和发动机 / 变速箱 / 驾驶室 / 底盘 / 车轮五项损伤与现有 `scs-telemetry.dll` 的遥测值
逐项核对；任何一项不匹配都会拒绝写入。

### 4.1 无限油量

进入驾驶界面、附加游戏后，直接勾选「**无限油量（自动补满并保持）**」。程序把车辆内部的
油量比例设为 `1.0`，并每 0.25 秒沿固定指针链取得当前车辆、校验后写回。

### 4.2 无损（永不损坏）

直接勾选「**车辆无损（五项清零并保持）**」。程序会一次清零并持续保持五个部件字段，换车或
读档后会沿同一条指针链自动跟随当前车辆，不会重新扫描。

### 4.3 发动机动力（直接改内存数值）

同一页的「**发动机动力（直接改内存数值）**」不需要模组，也不需要重启游戏：

* 动力倍率：`原厂` / `1.25×` / `1.50×` / `2.00×`，直接改写当前车辆的发动机峰值扭矩
  （例如 Volvo `d17a780` 原厂 `3800 N·m`，`1.25×` 即 `4750 N·m`）。
* 「转速上限 +10%」：同时把 `rpmLimit` 从 `2000` 提到 `2200`，用于提高极速。
* 「恢复原厂动力」：写回原值；分离进程、退出程序也会自动写回。

实现方式（v2，2026-09 稳定性修复后）：

* 定位路径为 `玩家上下文 + 0x150 → 附属总成数据容器 → 发动机数据对象`，容器内只读取
  4 KB；不做任何数值扫描。每次保持（每秒一次）都重新定位，因此**换车/换发动机/读档一定会
  被发现**；定位暂时失败时才退回上一次已验证过、且仍通过身份校验的对象。
* 发动机数据对象必须唯一命中（`torque`、`rpmIdle`、`rpmLimit`、`rpmLimitNeutral` 同时符合
  范围），命中 0 个或多个都会拒绝写入。
* 只缩放与基准扭矩同量级的字段（`+0x1C8`、`+0x264`、`+0x268`），不会误改相邻数值。
* **每个发动机对象各自保存「原厂基准」与「程序最后写入值」**：
  * 切换发动机对象前，先尽力把旧对象写回原厂值；
  * A → B → A 来回切换时，两个对象都按各自的记录恢复，不会把 `4750 N·m` 当成原厂值再放大；
  * 上一次运行的「写入值 / 原厂基准」会写进 `settings.ini`（`engine_state`），程序被强杀后
    下次启动也不会把放大值当原厂值。
* 关闭「转速上限 +10%」会立刻把 `rpmLimit` / `rpmLimitNeutral` 写回原厂值，动力倍率不受影响。
* 每次写入都检查返回值并回读验证；任何一项失败（含副本或 RPM 字段）都会**回滚到原厂值**，
  并在界面显示失败原因。
* 写入前做安全范围检查：结果必须是有限数，扭矩 `50–25000 N·m`、转速 `400–6000`；
  例如 `20000 N·m × 2` 会被拒绝且不写入，`7000 N·m × 2 = 14000` 允许写入且可恢复。
* 线程安全：配置、基准、对象地址、写入/恢复流程全部由同一把互斥量保护（不是把个别变量改成
  atomic）；界面快速连点与后台每秒保持不会互相踩状态。
* 恢复路径使用已保存地址，但写入前一定重新验证进程可用、地址可读、对象身份匹配；对象已失效
  或地址被复用时**只报告、不写**。
* 关闭方式都会写回原值：点「恢复原厂动力」、把倍率改回「原厂」、分离进程、重新附加、退出程序；
  析构时也会尽力写回，但只有在内存绑定仍然有效时才会访问。

#### 联机保护（含限制）

* **TruckersMP**：检查游戏进程内的模块与相关进程（如 `core_ets2mp.dll`），命中即拒绝写入。
  这条是严格的。
* **官方 Convoy**：游戏内置，没有额外进程/模块，只能依据 `Documents\Euro Truck Simulator 2\
  game.log.txt` 里的 `[MP] Session running.` / `Session closed.` 记录判定。
* 启用功能前会用最新状态复核一次；保持线程运行期间**每 5 秒复查一次**，命中就自动恢复原值并停止。
* **已知限制**：`game.log.txt` 读不到时状态显示「无法确认」，此时官方 Convoy **可能检测不到**；
  这个工具不会假装支持。TruckersMP 在 `game.log.txt` 里不写 `[MP]` 记录，所以 Convoy 判定对
  它无效，只能靠模块检测。
* 只做只读检测，不注入、不绕过任何反作弊。

> 实测（1.61.1.1，Volvo FH 2024 `d17a780`）：写入 `1.25×` 后 1.5 秒读回 `4750 N·m`，
> 三个扭矩字段同步变化；写回原值后恢复 `3800 N·m`。放大到 `14000 N·m` 后可保持、可恢复。
> 这些结论来自 2026-09 的 `--powertest` 单机实测与 10 项离线状态机测试。

### 4.4 小提示

* 不需要输入当前值，也不需要让油量/损伤先发生变化。
* 固定版本指纹用于确认 1.61.1.1；遥测交叉校验才是允许写入的最后条件。
* 新游戏版本不兼容时会显示“安全校验失败”，不会扫描或猜地址。
* 原手动车辆扫描只留在折叠的高级区用于兼容性排查；全内存扫描会增加内存压力。
* 联机（TruckersMP）不要用；官方 Convoy 也会被拦截，但判断依据是游戏日志（见 4.3 的说明）。

## 五、游戏内功能（控制台命令）

「游戏内功能」标签页会把命令**直接敲进游戏控制台**，游戏里即时生效：

| 命令 | 作用 |
| --- | --- |
| `g_set_time 12 0` | 游戏时间设为 12:00 |
| `g_police 0` | 关掉警察罚款 |
| `g_fatigue 0` | 关掉疲劳 |
| `g_income_factor 5.0` | 收入变成 5 倍 |
| `g_traffic 0` | 清空交通车流 |
| `g_fps 1` | 显示帧数 |

使用时修改器会把游戏窗口切到前台，按控制台键（默认 `~` 键）、输入命令、回车。
控制台需要在 `config.cfg` 里打开，本页面有「检测/开启控制台」按钮可一键处理（会先备份）。

> ⚠️ 这个功能会抢焦点，**开车途中别用**，先靠边停车（或暂停）再点。

### 5.1 飞行模式（自由相机）

同一页底部有「**飞行模式（自由相机）**」区域，把老式「复制 config.cfg」的做法做成了一键操作：

| 操作 | 说明 |
| --- | --- |
| 检查 config.cfg | 读取并显示 `g_developer`、`g_console`、`g_flyspeed` 的当前值 |
| 写入飞行模式设置 | 把上面三项写成 `1 / 1 / 你填的速度`；只改这三行，其余字节原样保留，首次修改前备份成 `config.cfg.trainer.bak` |
| 从 controls.sii 识别相机按键 | 按**你自己的**按键配置显示实际按键（不是照抄网上的说明） |
| 飞行速度 + 立即应用 | 等价于发送 `g_flyspeed 数值`，**不用重启游戏**即时生效 |
| 切换自由相机 | 把游戏窗口切到前台并发送开关键（默认数字键 `0`） |

**按键（欧卡2 默认绑定，本程序会读你的 `controls.sii` 显示实际值）**

| 按键 | 作用 |
| --- | --- |
| 数字键 `0`（`mix camdbg`） | 开/关自由相机 |
| 小键盘 `8` / `5` | 前进 / 后退 |
| 小键盘 `4` / `6` | 左 / 右 |
| 小键盘 `9` / `3` | 上升 / 下降 |
| 鼠标右键按住 | 转动视角 |

> 网上流传的「8 上升、9 下降」是旧版说明，实测（本机 `controls.sii`）是 **8=前进、9=上升、3=下降**。

**注意事项**

* 写入 `config.cfg` 前必须**完全退出游戏**：游戏退出时会重写该文件，运行中改会被覆盖。
  程序检测到游戏在运行会直接拒绝写入（不会做无用功）。
* 自由相机属于开发者功能，`g_developer 1` 同时也是控制台命令功能的前提，所以「开启」不会
  影响已有的控制台功能。
* 联机（官方 Convoy / TruckersMP）可能禁用开发者相机；本功能只改 `config.cfg` 和发送按键，
  **不写游戏内存**，但仍建议只在单机使用。
* 想改回原配置：用备份 `config.cfg.trainer.bak` 覆盖回去即可（或把 `g_developer` 手工改回 `0`）。

命令行只读检查：`ETS2Trainer.exe --flycheck` 会打印 config.cfg 状态、相机按键与「现在能不能安全写入」。

### 5.2 地图传送（控制台 `goto`）

欧卡2 自带开发者传送命令（从 1.61.1.1 二进制里读出的用法）：

```
goto X;Y;Z          传送坐标
goto X;Y;Z;A;E      传送坐标 + 朝向/俯仰
goto (城市名)        传送到城市（内部名，例如 berlin / calais）
goto (uid)          传送到某个物体
goto nav_start | nav_end | nav_next | nav_prev   沿导航点跳
goto back           回到上一个位置
```

「游戏内功能」页底部的「**地图传送（控制台 goto）**」把这些做成按钮：

| 功能 | 说明 |
| --- | --- |
| 读取城市列表（解密存档） | 解密当前存档并提取**城市内部名**；实测从 2.5 MB 加密存档里拿到 **314 个城市**，用时约 15 ms |
| 城市下拉 + 筛选 | 直接选一个城市 → 「传送到该城市」 |
| 城市名 / 坐标输入框 | `berlin` 或 `366.0;46.7;617.2`（坐标可从社区地图复制） |
| 导航起点 / 终点 / 下一个 / 上一个 | 对应 `goto nav_*`，沿 GPS 路线跳点 |
| 返回上一位置 | `goto back`，传送错了的保险绳 |
| 收藏点 | 把当前城市名/坐标存成名字，存进 `settings.ini`，下次一键传送 |

**城市名是怎么来的？** 欧卡2 存档里的仓库单位名是 `<公司>.<城市>`（例如 `tradeaux.berlin`）。
本工具扫描存档字节，取出所有「和至少两家公司配对」的地名，再剔除车型名（`volvo.fh_2021`）与
仓库后缀（`berlinb`），因此列表与**你安装的地图/DLC**一致，不是网上抄的。

**限制与注意事项**

* 传送走的是游戏自己的开发者命令，**不写游戏内存**，但需要开发者模式（见 5.1 / 控制台开关）。
* 传送后建议先停车或暂停，别在高速行驶中直接切；`goto back` 可以回到传送前的位置。
* 联机（TruckersMP / Convoy）里开发者命令可能被服务器限制或禁用，请只在单机使用。
* 城市名是内部名（德语/本地语写法，如 `munchen`、`wien`、`brussel`）；写错时游戏只会提示
  `City 'xxx' not found!`，不会造成损坏。

命令行只读检查：`ETS2Trainer.exe --citycheck` 会解密存档、打印提取到的城市名与耗时。

### 5.3 联运模式（Convoy / 联机）

欧卡2 的官方联机叫 **Convoy（联运）**：它不需要额外程序，游戏进程里没有第三方模块，所以原先只能靠
`game.log.txt` 里的 `[MP]` 会话记录判定；TruckersMP 是第三方联机，靠模块/进程检测判定。

现在已默认**关闭联运模式的检测**（`check_convoy=0`），官方 Convoy 中不再限制修改器功能（支持无限油量、车辆无损、发动机动力、地图传送与控制台等）。TruckersMP 则依然强制检测并禁用（避免封号）。

在「游戏内功能」页的「**联运模式（Convoy / 联机）**」区域中：

* **启用官方联运 (Convoy) 会话检测**（复选框）：默认**未勾选（已关闭检测）**，所有功能均可在联运中使用。
* 若显式勾选启用检测，则恢复联机拦截保护（严格模式全部禁用 / 联运模式仅放开不写内存功能）。
* **当前会话状态**：单机（联运模式检测已关闭）/ Convoy 会话进行中 / TruckersMP / 无法确认
* **在线玩家列表**：即使关闭拦截检测，仍可点击「读取玩家列表」从日志解析当前或最近的房间玩家。
* 配置保存在 `settings.ini` 的 `check_convoy`（0 = 关闭检测，1 = 开启检测）与 `mp_policy`。

命令行只读检查：`ETS2Trainer.exe --convoycheck` 会打印联机判定、会话时间与玩家列表。

## 六、存档工具

「存档工具」标签页会列出你所有存档（`Documents\Euro Truck Simulator 2\profiles` +
`steam_profiles` + Steam 云 `userdata\...\227300\remote\profiles`），可以：

* **备份选中存档** → 存到本目录的 `backups\` 里（含 `backup.json` 记录原始位置）
* **还原备份…** → 挑选一个备份；必须先退出游戏，确认后程序会先备份当前状态再还原
* **解密导出选中** → 把加密存档解密后导出到 `exports\`（方便自己分析）
* **明文存档改数值** → 如果某个存档是「明文(SiiNunit)」格式，可以直接改里面的现金/经验
  （写入前自动备份，只改 `bank.money_account` 和 `economy.experience_points` 两行）

### 为什么加密存档不能直接改？

新版欧卡2（1.5x 以后）的 `game.sii` 是 `ScsC` 格式：

```
[0:4]   "ScsC"
[4:36]  32 字节校验（游戏自己的密钥，无法伪造）
[36:52] AES 初始化向量
[52:56] 解密后长度
[56:]   AES-256-CBC 密文（固定密钥，本工具能解密）
```

本工具能**只读解密 + zlib 解压**（内层是 `BSII` 二进制格式），
但 `[4:36]` 的校验值算不出来，**强写加密存档有损坏存档的风险，所以本工具不写**。
要持久化金钱/经验，请用「实时改钱」改内存 → 游戏自动存档（这样写出的存档一定合法）。

> 解密导出的存档会写到 `文档\Euro Truck Simulator 2\exports\`。

**内存引擎要点**

* 只扫描可写内存区域（`PAGE_READWRITE` / `WRITECOPY` / `EXECUTE_*`）
* 自动排除两类"没用的大内存"：
  * **超过 1GB 的超大内存区**（显卡/驱动的内存池，欧卡2 有 8GB+ 这种区域）
  * **非缓存(PAGE_NOCACHE)内存**（设备/DMA 缓冲，约 600MB）
* 实测（你的机器，游戏运行中 5000 个区域）：跳过前首次扫描 91 秒 →
  跳过 1GB 大区后 28 秒 → 再加上排除非缓存内存后 **约 20 秒**（int32 约 10 秒）
* 分块 4MB 读取 + 多线程并行（默认 4 线程），带进度条和「取消」按钮
* 「再次扫描/收窄」只在候选地址上读取，所以是毫秒级（实测 **0.007 秒**）
* 浮点扫描：显示值会被取整（仪表盘 534 实际 534.75），所以按**容差**匹配。为不拖慢速度，
  先用 IEEE-754 全序把 float 映射成 uint32 做区间快速筛选，再逐值核对
* 锁定用后台线程每 0.25 秒写回一次

**C++ 版额外说明**

* 界面：Dear ImGui 1.92.9 + Direct3D 11 + Win32；自绘暗色主题、圆角控件、表格与进度条
* 字体：自动加载 `C:\Windows\Fonts\msyh.ttc`（微软雅黑，失败则依次尝试黑体/等线/宋体）
* 存档解密：AES-256-CBC 走 Windows CNG（bcrypt），zlib 解压是**自己实现的 DEFLATE**
  （RFC1951，含固定/动态哈夫曼与存储块），已用真实存档验证与标准 zlib 解压结果逐字节一致
  （SHA-256 相同）
* 扫描线程：`std::thread` 工作池 + 原子进度；界面线程只读原子状态，不阻塞渲染
* 单文件静态链接（`/MT`），不需要 VC++ 运行库；双击自动请求管理员权限

**数值类型经验**

* 现金（`money_account`）：**64 位整数**，所以默认选 `int64`
* 经验（`experience_points`）：**32 位整数**，默认 `int32`
* 油量 / 损坏：车辆固定指针链内为 **32 位浮点**（`float`），一键功能用遥测交叉校验

## 十、常见问题

**Q: 点「扫描」提示游戏没运行 / 附加失败？**
A: 先启动游戏；附加失败多半是权限问题，请以管理员身份运行 `ETS2Trainer.exe`。

**Q: 扫不到数值？**
A: ① 确认填的是游戏里**当前**显示的数值（不要带逗号也行，能自动去掉）；
② 试试换类型（现金用 `int64`，经验用 `int32`）；
③ 到「说明」页把“跳过超大内存区”改成 `0` 再扫（会慢但更彻底）。

**Q: 命中几百上千个怎么办？**
A: 用「收窄:数值变了」——在游戏里花钱/赚钱后把新数值填进去再收窄，两次就能降到个位数。

**Q: 无限油量 / 无损 怎么用？**
A: 进入驾驶界面并附加游戏，到「车辆（油量/无损）」页直接勾选对应功能。无需输入数值，
无需扫描或撞车收窄。

**Q: 油量/损坏扫不到，或者命中太多？**
A: 一键车辆功能不做任何数值扫描。如果提示版本指纹或结构校验失败，说明当前游戏版本、
驾驶状态或遥测插件不满足安全条件；进入驾驶界面后重试。不要强行写入多个未知候选地址。

**Q: 改完钱一会又变回去了？**
A: 勾选「锁定该数值」；或者改完立刻正常存档一次。

**Q: 联机（TruckersMP）能用吗？**
A: **强烈建议不要**。联机改内存可能违反 TruckersMP 规则导致封号，本工具检测到联机会警告，
并且不会自动帮你绕过。请只在单机使用。

**Q: 会不会把存档弄坏？**
A: 本工具不改加密存档；明文存档改写前会自动备份，且只改数值所在的那一两行（其余字节完全不变）。
随时可以在「存档工具」里还原备份。

## 十、后续功能探索（2026-09 只读调研结论）

用 `--enginetest`、`--fieldprobe` 和静态表导出（`tools\dev\dump_fields.ps1`）对 1.61.1.1
做过一轮只读调研，结论如下。

**已经具备、尚未做成功能的能力**

| 能力 | 证据 | 风险 |
| --- | --- | --- |
| 336 个控制台变量（玩法开关） | 二进制内 `g_*` 字符串全量导出 | 无（只发控制台命令） |
| 前瞻：关闭疲劳 / 警察 / 绕路 / 路况事件 / 强制休息，交通密度、停车难度、收入倍率、时间与天气 | 同上，变量名在 1.61.1.1 中确认存在 | 无 |
| 变速箱传动比数组（12 前进挡 + 4 倒挡） | `--fieldprobe`：变速箱对象 `+0x200` → `[11.73 9.21 7.09 …0.78]`，`+0x228` → `[-13.73 -10.78 -3.16 -2.48]`，与遥测插件发布的同一组数值逐项一致 | 中（写内存，需要上路验证物理效果） |
| 差速比 `differential_ratio = 3.08` | 变速箱对象 `+0x1C4`，同一对象由现有定位器唯一确认 | 中 |
| 遥测共享内存的多路信号 | 32 KB 映射：`+0x2BC` 比例、`+0x2C0` 油箱容量、`+0x2F0..0x30C` 每轮半径、`+0x330` 前进挡传动比、`+0x390` 倒挡传动比、`+0x3B4` 车速、`+0x3E8` 油量、`+0x40C..0x420` 磨损、`+0x2E4` 最大转速（与发动机数据 2000 rpm 一致） | 无（只读） |
| 车辆核心结构的全部字段 | 类型表 `0x141E1AFF0`：只有磨损、油量、用户相机/座椅等字段 | 无新增可玩项 |

**调研中发现的两点限制**

* 遥测插件**不发布**发动机扭矩与差速比，因此这两项无法用遥测交叉校验，只能靠结构范围 + 回读验证。
* `--fieldprobe` 在发动机对象里没有找到独立的扭矩曲线数组（曲线以 `+0x1C8 / +0x264 / +0x268`
  三个同量级副本的形式内联存在），所以动力调节仍然是改这三个值。

**建议的下一步（按性价比排序）**

1. **玩法设置一键包**（零风险、即时可用）：在「游戏内功能」页加一组开关，直接发送
   `g_fatigue 0` / `g_police 0` / `g_detours 0` / `g_road_events 0` / `g_mandatory_break 0` /
   `g_traffic` / `g_parking_difficulty` / `g_income_factor` 等命令，并显示当前值。
2. **实时仪表盘**（只读、零风险）：用现有遥测共享内存显示车速、油耗、磨损、传动比等；
   转速/档位/里程需要一次短时间的实时对照（例如跑 10 秒）才能确定通道偏移。
3. **传动比调节**（中等风险）：在现有动力调节旁边加「变速比」档位，写入前进挡/倒挡数组或
   差速比；写入前后用遥测发布的传动比做交叉校验，并保留同样的回滚与联机保护。
4. **防侧翻 / 物理类**（高风险，暂缓）：需要在每帧姿态或角速度上做修改，碰撞时容易抖动、
   弹飞甚至闪退，不适合在没有实车验证条件时启用。

> 以上都是**只读调研**结论；本轮没有向游戏写入任何数据，也没有改动现有功能的行为。
